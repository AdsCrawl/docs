发送 `{}`，使用已保存配置启动云浏览器。代理、Cookie 和指纹应在创建或更新配置时设置。使用请求头中的 API Key；若提供可选字符串 apiKeyId，它必须与该 Key 的 ID 相同。

<ParamField path="id" type="string" required>
  创建或列表返回的配置 UUID。
</ParamField>

<ParamField body="apiKeyId" type="string">
  可选；若提供，必须与 x-api-key 对应的 Key ID 一致。
</ParamField>

请求必须包含 JSON 对象；无可选字段时发送 `{}`，不能省略请求体。成功返回 HTTP 200、ok 和 runtime。以配置所有者身份登录浏览器后，打开返回的 connectUrl。适用时，runtime 还会包含 expiresAt 和 idleExpiresAt。

若客户端在收到响应前断开，先查询配置再决定是否重试；已接受的启动可能继续执行。

| HTTP 状态 | 含义 |
| --- | --- |
| 400 | JSON 或字段非法；空请求体非法。 |
| 401 | 需要有效账号 API Key。 |
| 402 | 需要付费套餐或足够余额，code 为 PAID_PLAN_REQUIRED 或 INSUFFICIENT_CREDITS。 |
| 403 | apiKeyId 与认证 Key 冲突。 |
| 404 | 当前账号无法访问该配置。 |
| 409 | 配置已活动、状态冲突，或并发已满（CLOUD_BROWSER_CONCURRENCY_LIMIT）。 |
| 429 | API Key 或用户会话上限已满。 |
| 503 | 运行服务不可用或容量不足。 |

## 请求与响应示例

```bash
curl "https://api.adscrawl.net/cloud-browsers/$BROWSER_ID/start" \
  -H "x-api-key: $ADSCRAWL_API_KEY" -H 'Content-Type: application/json' --data '{}'
```

```json
{
  "ok": true,
  "runtime": {
    "status": "running",
    "sessionId": "6a8a30ad-4788-46cf-a900-a1a1162478b2",
    "connectUrl": "https://app.adscrawl.net/dashboard/cloud-browser-viewer/?cloudBrowserId=7a631d48-afd7-47de-9fcb-8b57e62ccf75&sessionId=6a8a30ad-4788-46cf-a900-a1a1162478b2"
  }
}
```

## 认证

所有请求使用 `https://api.adscrawl.net`，并在 `x-api-key` 请求头中提供有效的账号 API Key。仅提供控制台 Cookie 或会话 JWT 会返回 HTTP 401。运行示例前设置 `ADSCRAWL_API_KEY`；操作单个配置时，将 `BROWSER_ID` 设为创建或列表接口返回的 UUID。
